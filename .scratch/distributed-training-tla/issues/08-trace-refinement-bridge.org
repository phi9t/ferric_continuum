* Question

How does a recorded Ferric ~tnsr.mesh_sim_trace.v0~ trace get checked to
refine the abstract step-transaction spec ~StepTxn.tla~, hermetically, under
the existing ~--config=formal~ TLC path?

* Context

Chosen by the 2026-09-15 wayfinder session:

- Arm = "invariants then trace": ~StepTxn.tla~ (issue 05) is the refinement
  target; this ticket is the first trace bridge that consumes it.
- Trace source = Ferric synthetic first: the bridge reads the existing
  ~MeshTrace~ / ~MeshTraceEvent~ schema emitted by the graduated DTensor mesh
  simulation (~ferric_continuum/tnsr/src/dtensor/trace.rs~), not a
  TorchTitan/Monarch schema.
- The refinement framing is inherited from arXiv:2602.22631 (TorchLean): a
  runtime artifact is only trustworthy if it *refines* a checked abstract
  spec. A trace linter with no spec is out of scope.

* Requirements

- A trace-to-behavior translator (Python, mirroring ~tools/tla_check.py~ /
  ~formal/distributed_training/tlc_bazel_test.py~) that:
  - reads a recorded ~MeshTrace~ JSON (one training step),
  - maps ~MeshTraceEvent~ variants to ~StepTxn.tla~ transitions
    (Collective -> synchronizing; phase Optimizer -> committing/committed;
    Failure -> aborting/aborted),
  - emits a TLA+ ~TraceBehavior~ module constraining the spec variables to the
    observed ordered sequence.
- A TLC check that the observed behavior is a legal behavior of ~StepTxn.tla~
  (refinement / trace-inclusion), reusing the pinned ~@tla2tools//jar~ and the
  ~mesh_plan_tlc_test~ hermetic scaffolding under ~--config=formal~.
- A good fixture (a legal recorded step -> TLC success/exit 0) and a bad
  fixture (a trace that violates the transaction contract, e.g. optimizer
  commit after a Failure event -> TLC exit 12 with a named invariant).
- The subset decision: which ~MeshTraceEvent~ variants the first refinement
  observes (Collective, Failure, Optimizer-phase) vs. ignores (LayoutTransition,
  Injection) with a written rationale.
- Never present a SKIP as PASS; the DTensor trace producer must be the
  graduated one.

* Out of scope

- TorchTitan/Monarch event schema (later frontier ticket).
- Layout/provenance (issue 04) and pipeline-buffer (issue 06) refinements.
- Recovery/checkpoint state (issue 07).
- Changing the ~tnsr~ trace emitter.

* Evidence needed

- The variant-subset table with rationale.
- The good/bad fixture pair and their TLC exit codes.
- The dependency edge from ~StepTxn.tla~ to the trace behavior module.

* Answer

Landed on branch ~formal-trace-bridge~ (cut from ~ultron/mainline~).

** How a recorded trace is checked to refine StepTxn.tla

1. Rust emits the real trace. ~MeshTrace::trace_json()~ (added to
   ~ferric_continuum/tnsr/src/dtensor/trace.rs~) serializes the graduated
   DTensor mesh simulation to the ~tnsr.mesh_sim_trace.v0~ schema; the
   ~//ferric_continuum/tnsr:dtensor_trace_dump~ binary writes it to disk
   (~--inject-failure~ adds a MissingParticipant injection on
   Backward/rank0/DpReplicate/AllReduce).
2. ~formal/distributed_training/trace_bridge.py~ classifies the trace
   (~classify_trace~) and renders a self-contained TLA+ behavior module +
   cfg (~render_behavior_module~ / ~render_config~) that ~INSTANCE~s
   ~StepTxn.tla~ over one rank, pins ~overflow~ to the observed value via
   ~ComputeObserved~, and asserts ~INVARIANT Inv~ + ~INVARIANT TraceConsumed~.
3. ~formal/distributed_training/trace_refine_bazel_test.py~ drives TLC
   hermetically (Bazel ~$(JAVA)~ + pinned ~@tla2tools//jar~) on both fixtures
   under ~--config=formal~ via
   ~//formal/distributed_training:trace_refine_tlc_test~.

** Variant-subset table (rationale)

| MeshTraceEvent variant | Observed? | Maps to / rationale                                  |
|------------------------+-----------+------------------------------------------------------|
| Collective             | yes       | -> synchronizing (AllReduce/AllGather = the barrier) |
| Failure                | yes       | -> aborting/aborted; sets ~overflow~ (abort path)    |
| phase == Optimizer     | yes       | -> committing/committed (the mutating commit)        |
| LayoutTransition       | no        | refines issue 04 (provenance), not the txn machine   |
| Injection              | no        | a stimulus, not a transition; effect shows as Failure|

** Good/bad fixtures and TLC exit codes

- ~trace_good.json~: real emitted commit-path trace (no failure). Refines
  StepTxn cleanly -> TLC success, exit 0.
- ~trace_bad.json~: synthetic commit-after-failure (collective + failure +
  optimizer-phase commit under an abort decision). Violates ~TraceConsumed~
  -> TLC "Error: Invariant TraceConsumed is violated", exit 12 with a
  counterexample. The Bazel driver additionally fails if the bad fixture is
  not the ~commit_after_failure~ case.

** Dependency edge

The generated behavior module ~INSTANCE StepTxn WITH Ranks<-{"r0"}, ...~ and
sets ~Inv==S!Inv~, ~TraceConsumed==CanAdvance \/ ENABLED DecideStep \/
(k>ObservedLen /\ S!Resolved)~, so the trace behavior module depends on
~StepTxn.tla~ (issue 05) as its refinement target.
