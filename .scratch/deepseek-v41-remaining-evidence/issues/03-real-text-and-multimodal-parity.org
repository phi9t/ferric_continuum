* Context

Text and multimodal tiny parity are already proven. Real released-weight parity
is not: current verifiers report an honest SKIP when no model directory is
configured, and the text verifier currently treats real-checkpoint execution as
a smoke check rather than numeric parity.

* Outcome Packet

Outcome:

- Real released-weight text and multimodal checks either pass with numeric
  candidate-bound evidence or remain explicitly unclaimable with a precise
  blocker.

Mode:

- delivery when admitted assets and reference runtime exist; scout when the
  environment cannot support numeric parity.

Non-goals:

- No native FP8/FP4 kernel performance claim.
- No tensor-parallel serving claim.
- No DSpark MTP parity; ticket 04 owns that.

Allowed external effects:

- Local read-only model checkpoint access.
- Local CPU/GPU reference execution within an explicit time and memory budget.

Escalation conditions:

- Upstream reference requires unavailable GPU-only kernels for a required claim.
- Real checkpoint execution exceeds memory or time budget.
- Rust and reference outputs disagree beyond tolerance.

* Requirements

- Define fixed text prompts/token-id inputs and fixed multimodal image fixtures
  used for real released-weight parity.
- Bind every parity run to:
  - code commit;
  - model asset receipt from ticket 02;
  - reference interpreter identity;
  - Rust binary path or Bazel target;
  - prompt/image input hashes;
  - comparator version.
- Extend verifiers so real-checkpoint levels can PASS only on numeric
  comparison, not on loader smoke.
- Preserve honest SKIP behavior when assets or faithful reference runtime are
  unavailable.
- Retain tiny parity as a lower-level guard, but do not let it satisfy this
  ticket's real-weight claim.

* Acceptance Map

Claim:

- Text logits from Rust match the real upstream checkpoint for fixed text
  inputs.

Evidence:

- Numeric comparator output with cosine, max_abs_diff, top-1, and top-5 overlap.

Claim:

- Multimodal logits from Rust match the real upstream checkpoint for fixed image
  prompts.

Evidence:

- Numeric comparator output plus image preprocessor receipt.

Candidate:

- Clean commit range plus admitted release model-dir receipt.

Reuse rule:

- Reuse only when candidate, model assets, prompt/image inputs, reference
  runtime, and comparator are unchanged.

Invalidation rule:

- Any change to loader, model forward, tokenizer/prompt/image path, comparator,
  reference adapter, or model assets reruns the affected parity.
