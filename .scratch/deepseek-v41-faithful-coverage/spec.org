* Summary

The current DeepSeek V4.1 implementation has a broad text/vision/DSpark scaffold,
but the reviewed runtime still leaves several release-defining mechanisms either
helper-only, fixture-only, or represented by names without faithful execution.

This kata turns those gaps into a blocker-linked queue. The acceptance bar is not
"a field exists"; each requested concept must have:

- a primary-source claim pinned in the verifier manifest,
- a small deterministic fixture or unit test,
- a runtime path that uses the mechanism, and
- a parity or behavior check that would fail if the implementation silently
  regressed to the current skeleton behavior.

* Faithfulness Contract

** CED

DeepSeek V4.1 Flash is a 40-layer model organized as 20 causal-encoder layers
followed by 20 decoder layers. Decoder global KV is projected from final encoder
hidden states. The local Rust path must stop treating the model as an
undifferentiated flat loop when global KV and DSpark target hidden states depend
on this boundary.

** CSA2

CSA2 has statically assigned =Full=, =Reindex=, and =Reuse= modes. Full produces
global KV and indexer state, Reindex reuses global KV but computes fresh Top-K
indices from its own query against shared indexer K, and Reuse reuses both global
KV and Top-K indices. Every mode still owns its local query and SWA KV.

** CSA from DeepSeek V4

The kata must preserve the contrast with DeepSeek V4 CSA: V4.1 uses pure CSA2,
removes the CSA/HCA hybrid framing, shares main KV and indexer K across layers,
and uses the V4.1 compressor/indexer flow rather than the older overlapping CSA
source-entry behavior. Where the upstream report says V4.1 differs from V4, the
Rust docs/tests should name that difference explicitly.

** Indexer Evolution

The indexer is not just a helper that picks integer windows. It is the small
attention path over compressed positions: =weights_proj=, indexer =wk=,
=k_norm=, indexer K cache, Top-K selection, optional hierarchical candidate
blocks, and candidate masks. The spec and fixtures should name the V3.2-origin
indexer lineage only where the local mirror has primary-source support, and the
runtime must implement the V4.1 behavior from the mirrored upstream code.

** Sliding-Window Attention

Every layer uses SWA. The runtime must use a ring-buffer/window index path in
actual attention, including prefill and decode behavior, rather than only testing
standalone index helpers.

** Engram

Engram is part of text compatibility, not a later vision-only extension. The
runtime must load Engram table tensors, compute compressed-token n-gram hashes
with image-token masking, perform table lookup and =wkv= projection, and apply
the residual update through the same gate semantics as upstream.

** DSpark MTP

DSpark lives under the =mtp.*= namespace and is represented by the upstream
=forward_spec= path. Prefill at =start_pos = 0= seeds caches and returns =None=;
decode uses =main_x= from =main_hidden=, =get_dspark_topk_idxs=, DSpark attention,
Markov logits, and confidence scores. A token-acceptance loop is outside this
kata unless a later ticket explicitly adds it.

** HF Indexed Release Loading

Faithful runtime tests must be able to load the public release shape:
=model.safetensors.index.json= and =model-000xx-of-00048.safetensors= shard
names. Converted TP-only paths are not enough for this queue.

* Resolution

This kata now captures and exercises the requested DeepSeek V4.1 mechanisms:
CED, Engram, CSA2, the DeepSeek V4 CSA/HCA contrast, the V3.2-origin indexer
lineage with V4.1 indexer runtime pieces, SWA, and DSpark MTP.

The faithful CPU surface is:

- primary-source manifest claims for all requested concepts,
- HF indexed-shard discovery and Engram tensor loading,
- CED encoder/decoder handoff through final encoder hidden state,
- CSA2 Full/Reindex/Reuse runtime state with SWA and compressed Top-K indices,
- Engram masked n-gram hashing plus loaded table lookup and =wkv= projection,
- DSpark =start_pos=-aware =forward_spec= behavior with =main_x=, Top-K
  attention, Markov logits, and confidence.
