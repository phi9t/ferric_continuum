* Context

CUDA is opt-in for Ferric. The first runner slice should record CUDA intent and
fail early when the host clearly cannot support a CUDA run, but it should not
yet implement CUDA projection mounts.

* Requirements

- Support ~--cuda~ as an explicit user request.
- Record CUDA intent in:
  - ~command.json~
  - ~preflight.json~
  - ~bwrap-plan.json~
- Preflight host CUDA signals such as:
  - ~/dev/nvidia*~
  - likely driver library roots
  - optional ~nvidia-smi~ path if present
- Fail before execution when ~--cuda~ is requested and required CUDA signals are
  absent.
- Keep CPU runs unaffected when ~--cuda~ is absent.
- Leave CUDA device/library projection for a follow-up ticket.

* Out of scope

- Mounting CUDA devices or driver libraries into bwrap.
- Validating a CUDA toolkit.
- Running Ferric CUDA Bazel tests.

* Verification

- Unit tests for CUDA preflight success/failure using temporary fake host paths.
- CLI dry-run test proving ~--cuda~ records intent.
- CLI dry-run test proving missing required CUDA signals fail before execution.
