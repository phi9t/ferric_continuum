* Goal

Finish the DTensor architecture experiment by clearing the redistribution
blocker, implementing three comparable dense-training tracer bullets, and
writing an evidence-based recommendation.

* Architecture

Keep the common substrate authoritative for mesh axes, layouts, shard mapping,
axis-local collectives, trace events, and deterministic injection. The three
architecture tracks should differ only in where distributed semantics live:
wrapper value, tensor metadata, or simulation plan. Each option must run the
same dense training scenario, emit the same trace vocabulary, and write a
short option-local report that ticket 08 can compare without reconstructing
the implementation history.

* Global constraints

- Dense mesh axes are exactly ~pp x dp_replicate x dp_shard x cp x tp~.
- MoE/EP, sparse meshes, CUDA/NCCL, async collectives, recovery, uneven shards,
  and real multi-process execution remain out of scope.
- ~Partial(sum)~ is the only supported reduction placement.
- Use the fixed dimension-aware reduce-scatter for ~Partial(sum) -> Shard(dim)~.
- Reuse common trace schema ~tnsr.mesh_sim_trace.v0~.
- Every option-local report must include:
  - supported semantics
  - unsupported semantics
  - reference-correctness evidence
  - trace and failure-localization evidence
  - files touched
  - interface complexity notes
  - recommendation for or against graduating the option
- Use pinned Bazel: ~bazel~.
- Commit, push, pull-request creation, branch landing, and final architecture
  selection require explicit human authorization.

        dst: Layout,
        sim: &mut CollectiveSimulator,

}
