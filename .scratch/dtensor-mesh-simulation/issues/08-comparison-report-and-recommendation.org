* Context

The DTensor mesh simulation effort should conclude with evidence, not a
preselected architecture.

- [[file:../plans/2026-08-18-remaining-architecture-options-plan.org][Remaining architecture options implementation plan]]

The comparison should explicitly use the lessons from the common substrate:
shape semantics, axis-local group reuse, trace/failure context, wrapper
low-risk control value, tensor-native blast radius, and plan-first observability.

* Requirements

- Compare all three tracer bullets against the same rubric:
  - semantic expressiveness
  - correctness against unsharded reference
  - collective/cost/topology trace quality
  - chaos failure localization
  - interface complexity
  - existing code touched
  - test complexity
  - suitability for future full forward/backward foundation-model training mesh
    simulation
- Recommend which architecture should graduate to durable implementation.
- Identify shared infrastructure that should remain regardless of the winning
  architecture.
- Identify discarded or deferred pieces and why.
- Record follow-up work for MoE/EP, asynchronous collectives, real backends, or
  richer recovery if the evidence supports them.
- Read the three option-local reports:
  - ~.scratch/dtensor-mesh-simulation/reports/05-wrapper-dtensor.org~
  - ~.scratch/dtensor-mesh-simulation/reports/06-tensor-native-layout.org~
  - ~.scratch/dtensor-mesh-simulation/reports/07-plan-first-simulation.org~
- Write the final comparison report to
  ~.scratch/dtensor-mesh-simulation/reports/08-comparison.org~.
- Include a decision table with one row per architecture and these columns:
  - interface size
  - files touched
  - unsupported semantics
  - trace quality
  - chaos localization quality
  - reference correctness evidence
  - risk to existing ~tnsr~ local tensor/autograd behavior
  - recommendation
- Update ~../spec.org~ with a short pointer to the selected durable direction
  only after the evidence report is complete.
- Separate the final recommendation into:
  - architecture to graduate
  - common substrate pieces to keep regardless of winner
  - test/observability infrastructure to keep even if not user-facing
  - deferred risks that block claims of full TorchTitan parity
- Do not select an architecture before reading the three option-local reports.

* Out of scope

- Implementing the final durable architecture beyond the tracer bullets.
- Landing a branch, pushing, or creating a pull request without explicit human
  approval.

* Verification

- The comparison report cites concrete tests, trace artifacts, and code paths
  from each tracer bullet.
- Every blocking finding or unknown is either resolved or converted into an
  explicit follow-up ticket.
- The recommendation is evidence-based and does not select an architecture only
  because it was initially preferred.
- The report includes at least one follow-up ticket for the durable direction
  and one for the first deferred non-dense extension if the evidence supports
  continuing.
