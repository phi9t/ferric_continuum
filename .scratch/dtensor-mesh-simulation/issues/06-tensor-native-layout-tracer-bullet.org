* Context

Option B tests native layout metadata in or next to the core ~Tensor~ type.
The goal is to measure ergonomics and blast radius, not to make every existing
operation distributed-aware in one step.

Planning inputs:

- [[file:../reports/04-common-substrate-reflection.org][Common substrate reflection]]
- [[file:../plans/2026-08-18-remaining-architecture-options-plan.org][Remaining architecture options implementation plan]]

This option is primarily a blast-radius and ergonomics experiment. The result
is useful only if it proves both what gets easier and what existing local tensor
surface had to change.

* Requirements

- Add optional distribution metadata to ~TensorInner~ or a closely adjacent
  core type.
- Prefer the least invasive native surface that still answers the ergonomics
  question. A concrete acceptable surface is:

#+begin_src rust
pub struct TensorLayoutMeta {
    pub global_shape: Shape,
    pub layout: Layout,
    pub dims: ParallelDims5D,
    pub rank: usize,
}

impl Tensor {
    pub fn with_layout_meta(self, meta: TensorLayoutMeta) -> Self;
    pub fn layout_meta(&self) -> Option<TensorLayoutMeta>;
}
#+end_src

- Keep layout propagation constrained to the shared training-step harness.
- Reuse the common mesh, placement, shard map, collective simulator, trace, and
  injection semantics.
- Run the same harness scenario as the other tracks.
- Record which existing op seams had to change.
- Emit shared telemetry and deterministic failure records.
- Compare how native semantics affect interface complexity, locality, and
  normal local tensor code.
- Prove that existing local tensor behavior is unchanged when no layout metadata
  is attached.
- Keep metadata attachment explicit and avoid silent propagation through
  arbitrary existing ops.
- Include at least one unsupported-propagation test that returns a typed error.
- Record exact core tensor/autograd/op seams touched in the option-local report.
- Write a short option-local report under
  ~.scratch/dtensor-mesh-simulation/reports/06-tensor-native-layout.org~.

* Out of scope

- Making every ~tnsr~ op layout-aware.
- Allowing silent layout propagation for unsupported ops.
- Replacing the wrapper or plan-first tracks.
- Real distributed execution.
- Multi-axis placement propagation.
- Changing existing op math.

* Verification

- Existing local tensor behavior remains unchanged when no layout metadata is
  present.
- Harness output matches the unsharded reference for supported slices.
- Unsupported layout propagation fails loudly.
- Trace and injection tests match the common schema.
- Tests cover at least:
  - attaching and reading layout metadata
  - a local op that preserves no metadata unless explicitly supported
  - one explicitly supported training-step boundary that consumes metadata
  - failure on unsupported native-layout propagation
  - unchanged existing autograd/lib tests

** Review fix round 1

Reviewer finding addressed: ~redistribute_native_training_step_boundary~ did
not validate that ~CollectiveSimulator::dims~ matched the
~TensorLayoutMeta::dims~ carried by native tensors. A same-world-size simulator
with different axis factorization could compute and trace under one mesh while
returned tensor metadata described another.

Fix:

- Added typed ~NativeLayoutError::SimulatorDimsMismatch { metadata, simulator }~.
- Added the mismatch check immediately after native tensor metadata validation
  and before any no-op return, simulator redistribution call, or trace event.
- Added
  ~native_layout_rejects_simulator_dims_mismatch_with_same_world_size~. The test
  uses metadata dims ~ParallelDims5D::new(1,1,1,1,4)~ and simulator dims
  ~ParallelDims5D::new(1,1,2,1,2)~. Both have world size 4, but the axis
  factorization differs.
