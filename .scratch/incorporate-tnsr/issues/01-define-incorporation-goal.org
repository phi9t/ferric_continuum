* Question

What does "incorporate `~/workspace/tnsr` into this repo" mean for this effort?

Resolve the intended outcome before any import work starts. In particular, decide whether the destination is:

- selective feature port into `ferric_continuum/tnsr`
- full source import with manual reconciliation
- history-preserving subtree/filter-repo import
- archival/reference import only
- some mix of the above by artifact category

The answer should state the success criteria in terms future `/to-spec` and `/to-tickets` runs can use.

* Context

`ferric_continuum/tnsr` already exists and is Bazel-integrated. It includes autograd, ops, transformer/Qwen3 paths, CUDA forward support, symbolic scaling/distributed modules, tests, and HuggingFace numeric-compat tooling.

`~/workspace/tnsr` is a separate Cargo-first repo. It overlaps core Rust source files and adds material not obviously present in the monorepo, including a playground CLI, CPU inference primitives, memory/parallelism reports, docs/debugging.md, examples, and a Vite/Three.js trace viewer.
