* Question

What does "incorporate `~/workspace/tnsr` into this repo" mean for this effort?

Resolve the intended outcome before any import work starts. In particular, decide whether the destination is:

- selective feature port into `ferric_continuum/tnsr`
- full source import with manual reconciliation
- history-preserving subtree/filter-repo import
- archival/reference import only
- some mix of the above by artifact category

The answer should state the success criteria in terms future `/to-spec` and `/to-tickets` runs can use.

* Context

`ferric_continuum/tnsr` already exists and is Bazel-integrated. It includes autograd, ops, transformer/Qwen3 paths, CUDA forward support, symbolic scaling/distributed modules, tests, and HuggingFace numeric-compat tooling.

`~/workspace/tnsr` is a separate Cargo-first repo. It overlaps core Rust source files and adds material not obviously present in the monorepo, including a playground CLI, CPU inference primitives, memory/parallelism reports, docs/debugging.md, examples, and a Vite/Three.js trace viewer.

* Comments

* Answer

Incorporation means a selective feature port into the existing Bazel-integrated `ferric_continuum/tnsr` module.

This effort should not treat `~/workspace/tnsr` as a replacement tree. The monorepo remains the destination and source of truth for current `tnsr` behavior unless a later ticket explicitly decides otherwise for a narrow artifact. Existing Qwen3, CUDA, GQA/RoPE, distributed teaching, HuggingFace numeric-compatibility, and Bazel integration work must be preserved.

The default import policy is:

- port useful external features and tests intentionally
- reconcile overlapping Rust modules file by file
- adapt imported material to the Bazel-built monorepo
- keep Cargo manifests as tooling mirrors, not primary validation
- avoid generated artifacts such as `web/dist`, `web/test-results`, and `web/node_modules`
- avoid history-preserving subtree/filter-repo import unless the history-policy ticket finds a specific need

Success criteria for this map:

- identify exactly which `~/workspace/tnsr` artifacts should land
- define destination paths and Bazel targets for accepted artifacts
- record which overlapping monorepo files remain source of truth
- decide whether the web trace viewer is in scope
- define a verification matrix that protects existing monorepo behavior
- collapse the decisions into a spec and implementation tickets
