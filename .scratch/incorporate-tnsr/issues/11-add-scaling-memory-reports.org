* Context

The external repo's scaling memory concepts should become a Bazel-tested monorepo scaling module. Existing `ferric_continuum/tnsr/src/scaling/model_stats.rs`, `report.rs`, and `distributed/fsdp.rs` already own nearby concepts, so this ticket must reconcile overlap rather than creating a competing report stack.

This ticket should land before broad parallelism report reconciliation.

* Requirements

- Add `ferric_continuum/tnsr/src/scaling/memory.rs`.
- Export it from `ferric_continuum/tnsr/src/scaling/mod.rs`.
- Add the new source file to `_TNSR_SRCS` in `ferric_continuum/tnsr/BUILD.bazel`.
- Implement parameter, optimizer-state, gradient, activation, and KV-cache byte estimates where they fit the existing scaling model.
- Add ZeRO/FSDP partitioning summaries only where they complement existing `scaling/distributed/*` APIs.
- Add golden-value tests under `ferric_continuum/tnsr/tests/`.
- Add a Bazel target such as `//ferric_continuum/tnsr:scaling_memory_tests`.
- Document formulas close to the code.

* Out of scope

- Replacing existing scaling report modules wholesale.
- Introducing a second competing model for FSDP/ZeRO semantics.
- Changing distributed simulation behavior except where required to share a formula or type.

Implemented a Bazel-tested `tnsr::scaling::memory` module in the primary Ferric Continuum checkout after isolated development and review.

Files changed:

- `ferric_continuum/tnsr/src/scaling/memory.rs`
- `ferric_continuum/tnsr/src/scaling/mod.rs`
- `ferric_continuum/tnsr/BUILD.bazel`

Behavior added:

- Parameter, gradient, Adam optimizer-state, bf16 master-weight, activation, and KV-cache byte estimates for `TransformerConfig`.
- `TrainingMemoryConfig` and `TrainingMemoryReport` as the public memory-report interface.
- `Precision`, `ActivationCheckpointing`, and `ZeroStage` policy enums for formula selection.
- `zero_partitioned_memory` as a convenience view that uses the existing distributed FSDP return type while keeping communication semantics owned by `scaling::distributed::fsdp`.
- Golden-value tests for default f32 memory, checkpointing modes, bf16 ZeRO-3, KV cache, Stage1/Stage2 partitioning, and non-divisible shard rounding.

Review and repair:

- Initial ticket review found that selective activation estimates did not match runtime `TransformerSelectivePolicy`, and that `training_memory_report` and `zero_partitioned_memory` used inconsistent rounding.
- Fixed selective activation estimates to save `AttentionScores`, save `AttentionMix`, save `Softmax` only below the small-save threshold, and recompute GELU, LayerNorm, and large Linear sites.
- Fixed public memory rounding so `training_memory_report` and `zero_partitioned_memory` both use ceil-rounded sharded byte ownership.
- Scoped re-review found no remaining blocker.
