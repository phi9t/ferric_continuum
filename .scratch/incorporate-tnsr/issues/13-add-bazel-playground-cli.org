* Context

The external `src/playground.rs` and `src/bin/tnsr-demo.rs` are source material for a maintained monorepo demo/debug binary. The binary should demonstrate current Ferric Continuum APIs through Bazel.

This ticket follows the APIs it demonstrates. If one of the prerequisite API slices is intentionally skipped, record that in this ticket before implementation.

* Requirements

- Decide whether to extend existing `//ferric_continuum/tnsr:tnsr_demo` or add a separate binary such as `//ferric_continuum/tnsr:tnsr_playground`.
- If a separate binary is added, place source under `ferric_continuum/tnsr/src/bin/` and add a Bazel `rust_binary` target.
- Use `@crates//:clap` only if flags/subcommands justify it. `clap` is already a direct crate spec in `MODULE.bazel`.
- Demonstrate current monorepo APIs, not stale external APIs.
- Write generated demo artifacts to temp/output paths.
- Add a focused `//ferric_continuum/tnsr:playground_cli_tests` target if CLI logic is meaningful and cleanly testable; otherwise record explicit `bazel run` smoke commands.

- Cargo-only examples.
- Checking in generated `.dot`, `.json`, `target/`, or example output artifacts unless a later ticket explicitly chooses small golden fixtures.
- Importing frontend viewer tooling.

Implemented in the existing Bazel target
~//ferric_continuum/tnsr:tnsr_demo~ rather than adding a second binary.

- Added a small shared ~tnsr::playground~ module for demo CLI option parsing.
- Added ~--dot PATH~ and ~--trace-json PATH~ to write generated artifacts to
  caller-selected output paths; the no-flag default remains ~/tmp/block.dot~.
- Extended the demo to show the current training memory-report API alongside
  the existing autograd, checkpointing, scaling, and distributed reports.
- Added ~//ferric_continuum/tnsr:playground_cli_tests~ for the meaningful CLI
  logic.
- Added a fallible DOT rendering path for the demo so caller-selected bad output
  paths exit nonzero instead of logging a false success.
