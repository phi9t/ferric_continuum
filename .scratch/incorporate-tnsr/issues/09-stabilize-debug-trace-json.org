* Context

`ferric_continuum/tnsr/src/debug.rs` is the monorepo-owned debug surface. The external repo's web viewer parser at `/data02/home/philip.yang/workspace/tnsr/web/src/trace.ts` is reference material only; the Rust schema should be owned by the monorepo API.

This ticket should land before any future viewer work so downstream tooling can target a stable trace format.

- Add or extend tests under `ferric_continuum/tnsr/tests/`.
- Add a focused Bazel test target such as `//ferric_continuum/tnsr:debug_trace_tests` if the existing targets are not a clean fit.

- Adding frontend, npm, Vite, Three.js, Playwright, browser, WebGL, or screenshot checks.
- Replacing `debug.rs` with the external implementation.

* Answer

Implemented a stable Rust-owned debug trace JSON export on `DebugRecorder`.

- Added `DebugRecorder::trace_json()` and `DebugRecorder::trace_json_pretty()`.
- Extended `OpCallRecord` with input tensor ids, input grad flags, and output tensor ids so exported traces include real graph edges.
- Exported schema metadata, replayable `events`, normalized `forward_ops`, `saved_sites`, `checkpoints`, `backward_ops`, and `grad_accumulations`.
- Kept the schema owned by the Rust API. The external viewer parser was reference material only.
- Added `//ferric_continuum/tnsr:debug_trace_tests` to assert stable schema fields over a multi-op forward/backward trace.
