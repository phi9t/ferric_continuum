#+TITLE: Incorporate external tnsr into Ferric Continuum
#+TYPE: wayfinder:map
#+STATUS: resolved

* Destination

Produce a decision-backed incorporation plan for bringing useful material from `~/workspace/tnsr` into this Bazel-built monorepo without regressing the existing `ferric_continuum/tnsr` module. The active effort is complete when selected material is incorporated, Ferric Continuum passes final verification, the standalone checkout is audited, Ultron stops tracking `tnsr`, and the standalone checkout is archived before deletion.

* Notes

- Consult `${HOME}/workspace/ferric_continuum/docs/agents/domain.md` and `${HOME}/workspace/ferric_continuum/docs/agents/issue-tracker.org`.
- Treat `ferric_continuum/tnsr` as the current Bazel-integrated target, not a blank destination.
- Treat `~/workspace/tnsr` as a Cargo-first source repo containing overlapping Rust core files, CPU inference primitives, playground CLI, tests, docs, examples, and a Vite/Three.js trace viewer. It is a temporary source reference until the archive-first retirement tickets are complete.
- Preserve the repo's Bazel-first workflow. Cargo manifests may exist for Rust tooling, but implementation landing must keep Bazel targets coherent.
- Decisions should prefer selective, reviewed incorporation over wholesale overwrite.

* Decisions so far

- [[file:issues/01-define-incorporation-goal.org][Define what incorporation means]] — incorporate `~/workspace/tnsr` by selective feature port into the existing Bazel-integrated `ferric_continuum/tnsr`; do not overwrite the module or preserve external history by default.
- [[file:issues/02-inventory-external-artifacts.org][Inventory external tnsr artifacts]] — use `~/workspace/tnsr` as selective source material: monorepo is newer for Qwen3/CUDA/distributed/Bazel paths, while external repo contributes likely import-worthy CPU inference, playground, memory/parallelism reports, docs/examples, and web viewer assets.
- [[file:issues/03-decide-source-of-truth-for-overlaps.org][Decide source of truth for overlapping Rust modules]] — keep monorepo shared core/ops/transformer/scaling files as source of truth; port external behavior selectively as new/adapted APIs, tests, and docs.
- [[file:issues/04-decide-bazel-integration-boundary.org][Decide Bazel integration boundary]] — accepted Rust artifacts must land as first-class Bazel library/binary/test/doc targets; Cargo remains a tooling mirror, and web tooling is deferred to the web-scope decision.
- [[file:issues/05-decide-web-viewer-scope.org][Decide web trace viewer scope]] — keep the Vite/Three.js viewer out of this incorporation batch; treat `~/workspace/tnsr/web` as reference material until a separate frontend/tooling effort exists.
- [[file:issues/06-decide-history-policy.org][Decide history preservation policy]] — do not use subtree/filter-repo/submodule import by default; port selected behavior as normal Ferric Continuum commits and cite external paths or commits when useful.
- [[file:issues/07-decide-verification-matrix.org][Decide verification matrix]] — require Bazel build/test validation for every Rust slice, add focused tests for accepted imports, keep Cargo checks supplementary, require Qwen3/CUDA checks only when touched, and exclude web checks from this batch.
- [[file:issues/08-collapse-map-to-build-spec.org][Collapse incorporation decisions into build spec]] — resolved the map into [[file:spec.org][spec.org]], with implementation slices, dependency order, accepted destinations, out-of-scope artifacts, validation commands, and landing expectations.
- [[file:issues/12-reconcile-parallelism-reports.org][Reconcile selected parallelism reports]] — folded external parallelism summary concepts into existing distributed scaling reports without adding a competing module; kept pipeline scheduling in `distributed::pipeline`, exposed schedule microbatch count, microbatch size, step-level pipeline handoff bytes, activation sharding factor, and symbolic collectives with Bazel tests.
- [[file:issues/13-add-bazel-playground-cli.org][Add Bazel-backed playground/debug CLI]] — extended the existing `//ferric_continuum/tnsr:tnsr_demo` target with dependency-free `--dot` and `--trace-json` artifact flags, added `tnsr::playground` parser tests, exercised the current memory report API, and fixed the demo path to fail loudly on DOT write errors.
- [[file:issues/16-audit-standalone-tnsr-before-retirement.org][Audit standalone tnsr before retirement]], [[file:issues/17-remove-tnsr-from-ultron-tracking.org][Remove tnsr from Ultron tracking]], and [[file:issues/18-archive-delete-standalone-tnsr.org][Archive and delete standalone tnsr]] — extend the end state: after final verification, audit standalone-only work, remove `tnsr` from Ultron tracking with an explicit manifest assertion, archive the checkout with recorded evidence, then delete the active checkout only with explicit final deletion authority.
