#+TITLE: Distributed training formal models

* Scope

This directory contains Ferric Continuum's first executable formal-modeling
artifacts for robust N-D distributed training.

The first model, ~MeshPlan.tla~, is intentionally small. It treats collectives
as atomic operations and checks whether a planned launch order over overlapping
process groups can make every rank busy while no collective can complete.

This slice inherits vocabulary from the DTensor mesh simulation handoff:

- ordered process-group membership;
- per-rank collective launch order;
- collective descriptors with operation kind, tensor identity, shape, dtype,
  reduction, root, input/output layout, membership generation, step, slot, and
  epoch;
- atomic collective completion before packet-level protocol details.

* Files

- ~MeshPlan.tla~: abstract collective-ordering model.
- ~MeshPlanGood.tla~ and ~MeshPlanGood.cfg~: a concrete DP x TP schedule where
  TP collectives complete before DP collectives.
- ~MeshPlanBad.tla~ and ~MeshPlanBad.cfg~: the canonical DP x TP cross-axis
  ordering cycle.
- ~StepTxn.tla~: the Layer-0 step-transaction contract. A training step is a
  distributed transaction over a versioned device mesh: each rank walks an
  idle -> computing -> synchronizing -> prepared -> {committing/committed |
  aborting/aborted} phase machine; the group takes exactly one global
  commit/abort decision (commit iff no rank observed an AMP/loss-scale
  overflow); committed model versions increase monotonically; and no optimizer
  state mutates on the abort path. This is the refinement target for the first
  runtime trace bridge (~.scratch/distributed-training-tla/issues/08~).
- ~StepTxnGood.tla~ and ~StepTxnGood.cfg~: a legal two-rank instance; satisfies
  ~Inv~ and the ~StepResolves~ liveness property.
- ~StepTxnBad.tla~ and ~StepTxnBad.cfg~: a buggy variant whose ~AbortMutating~
  action mutates optimizer state and bumps the version on the abort path,
  violating ~NoMutationAfterAbort~ / ~VersionMonotone~.

* Runner

Use ~tools/tla_check.py~ to record checker evidence.

Dry-run evidence works without a local TLC installation:

#+begin_src sh
python3 tools/tla_check.py \
  --model formal/distributed_training/MeshPlanGood.tla \
  --config formal/distributed_training/MeshPlanGood.cfg \
  --out-dir .ferric/tla/mesh-plan-good \
  --dry-run
#+end_src

When ~tla2tools.jar~ is available (ad-hoc host run):

#+begin_src sh
python3 tools/tla_check.py \
  --tla-tools-jar /path/to/tla2tools.jar \
  --java-bin /path/to/jdk17/bin/java \
  --model formal/distributed_training/MeshPlanGood.tla \
  --config formal/distributed_training/MeshPlanGood.cfg \
  --out-dir .ferric/tla/mesh-plan-good

python3 tools/tla_check.py \
  --tla-tools-jar /path/to/tla2tools.jar \
  --java-bin /path/to/jdk17/bin/java \
  --model formal/distributed_training/MeshPlanBad.tla \
  --config formal/distributed_training/MeshPlanBad.cfg \
  --out-dir .ferric/tla/mesh-plan-bad
#+end_src

TLC needs a modern JDK (17+); tla2tools no longer runs on Java 8. Pass
~--java-bin~ to point at the right launcher when the host default is too old.

* Hermetic Bazel path (canonical)

The canonical way to run the model check is under Bazel, which needs *no* host
~java~ and *no* ~TLA_TOOLS_JAR~. Bazel fetches the pinned ~tla2tools.jar~ (via
the ~@tla2tools~ ~http_jar~ in ~MODULE.bazel~, verified by sha256) and runs
~tlc2.TLC~ with a pinned hermetic JDK 17. The ~--config=formal~ flags in
~.bazelrc~ select ~remotejdk_17~ (the auto-detected host ~local_jdk~ can be
Java 8, which is too old).

#+begin_src sh
# Full verifier: runner unit tests + hermetic good/bad TLC check.
# NEVER presents a SKIP as PASS; SKIPs the TLC level honestly when offline.
bash formal/tools/verify_formal_mesh_plan.sh

# Or run the hermetic TLC check target directly:
bazel test --config=formal //formal/distributed_training:mesh_plan_tlc_test

# The Layer-0 step-transaction contract (StepTxn good/bad pair):
bazel test --config=formal //formal/distributed_training:step_txn_tlc_test

# The mesh-trace -> StepTxn refinement bridge (real recorded trace):
bazel test --config=formal //formal/distributed_training:trace_refine_tlc_test

# Runner unit tests only (pure Python, no jar/JDK):
bazel test //tests/tla_check:tla_check_test
#+end_src

The ~mesh_plan_tlc_test~, ~step_txn_tlc_test~, and ~trace_refine_tlc_test~
targets are tagged ~local-only~ + ~manual~ because they fetch the jar over the
network at repo-rule time, so plain ~bazel test //...~ skips them. GitHub CI
runs them in the dedicated ~formal~ job via the verifier above.

Expected behavior:

- ~MeshPlanGood.cfg~ satisfies ~Inv~ and ~CollectiveResponse~ in the finite
  DP x TP instance (~result = success~, TLC exit ~0~).
- ~MeshPlanBad.cfg~ violates ~Inv~ through ~BlockedCycle~ (~result =
  invariant_violation~, TLC exit ~12~), showing the cross-axis collective
  ordering bug. The nonzero exit is the *expected* outcome, so the test asserts
  on the classified result, not the raw exit code.

~Inv~ includes the first topology checks: unique DP/TP rank coordinates, ordered
local-rank membership without duplicates, per-rank agreement on ordered group
views, no ghost members, posted-by-member validity, completion only after all
required members posted, signature agreement for each group/epoch/step/slot, and
no blocked cycle.

For ~StepTxn~:

- ~StepTxnGood.cfg~ satisfies ~Inv~ and the ~StepResolves~ liveness property
  (~result = success~, TLC exit ~0~).
- ~StepTxnBad.cfg~ violates ~Inv~ (~NoMutationAfterAbort~ / ~VersionMonotone~)
  because ~AbortMutating~ touches optimizer/version state on the abort path
  (~result = invariant_violation~, TLC exit ~12~).

~StepTxn.Inv~ bundles: ~TypeOK~, ~OneGlobalDecision~ (one group-wide
commit/abort governs every rank), ~NoMutationAfterAbort~, ~VersionMonotone~
(version rises at most once and only under a commit decision), and ~NoSkipSync~
(no rank commits/aborts without a resolved global decision).

For the mesh-trace -> StepTxn refinement bridge (issue 08):

- ~trace_good.json~ is a real ~tnsr.mesh_sim_trace.v0~ trace emitted verbatim
  by ~//ferric_continuum/tnsr:dtensor_trace_dump~ (the graduated DTensor mesh
  simulation). ~trace_bridge.py~ translates it into a self-contained behavior
  module that ~INSTANCE~s ~StepTxn.tla~ over one rank, pins ~overflow~ to the
  observed value, and asserts ~INVARIANT Inv~ + ~INVARIANT TraceConsumed~. The
  observed commit-path behavior refines ~StepTxn~ cleanly (~result = success~,
  TLC exit ~0~).
- ~trace_bad.json~ is the canonical illegal commit-after-failure observation
  (a collective + a failure + an optimizer-phase commit under an abort
  decision). It violates ~TraceConsumed~ (~result = invariant_violation~, TLC
  exit ~12~) with a counterexample.

Variant-subset (first refinement): the bridge observes ~Collective~ (->
synchronizing barrier), ~Failure~ (-> abort path / sets ~overflow~), and phase
~Optimizer~ (-> committing/committed). It ignores ~LayoutTransition~ (refines
issue 04, not the txn machine) and ~Injection~ (a stimulus, not a transition;
its effect shows up as ~Failure~).

If no checker is installed, a non-dry run exits with code ~2~ and writes
~tla-check.json~ with ~checker = \"missing\"~. A dry run still exits with code
~0~ and records the command it would have used.
