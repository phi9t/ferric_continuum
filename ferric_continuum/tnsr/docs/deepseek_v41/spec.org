* Goal

Implement DeepSeek V4.1 Flash in =ferric_continuum/tnsr= as an inspectable,
text-only causal-LM path first, with a verifier ladder that proves the Rust
implementation stays compatible with the upstream paper/model-card claims, the
Hugging Face checkpoint metadata, and DeepSeek's released inference code.

The first implementation wave must produce text logits. Multimodal image input
and DSpark speculative decoding remain explicit TODO waves.

* Scope

** Wave 0: source evidence and verifier fixtures

Create durable source-manifest fixtures that encode the exact upstream facts
the implementation must satisfy. These fixtures are not a replacement for the
paper or upstream code; they are a local, testable index of cited claims.

Required verifiers:

- A paper/model-card claim verifier checks that the local source manifest still
  agrees with the mirrored README and technical report facts used by this
  implementation.
- A config verifier checks nested Hugging Face =config.json= and flat
  =inference/config.json= against the expected DeepSeek V4.1 text fields.
- A safetensors-index verifier checks the release checkpoint namespace and
  shard map without downloading hundreds of GB of weight data.
- A source-surface verifier checks that the upstream inference code still
  exposes the functions/classes relied on by parity fixtures.

** Wave 1: text-only implementation

Implement the text causal-LM path:

- Text config parser for both HF nested config and DeepSeek inference config.
- Interleaved YaRN RoPE matching upstream =apply_rotary_emb=.
- Sliding-window sparse attention indices.
- Compressed KV compressor and indexer metadata/seams.
- Latent attention with =wq_a=, =q_norm=, =wq_b=, =wkv=, =kv_norm=,
  =attn_sink=, grouped =wo_a=, and =wo_b=.
- MoE gate with =sqrtsoftplus= scoring, correction bias, unbiased routing
  weights, =norm_topk_prob=, and =routed_scaling_factor=.
- Routed and shared SwiGLU experts with =swiglu_limit= clamps.
- Hyper-Connection residual copies and Sinkhorn-derived pre/post/comb mixes.
- Engram compressed-token map, hash layout, n-gram hash state, lookup module,
  and residual update for text tokens.
- Text transformer forward: embedding -> HC expansion -> 40 text blocks ->
  collapse -> final RMSNorm -> head logits.
- Loader support for the DeepSeek checkpoint namespace, with explicit handling
  of HF/converted names, transposes, TP shard dimensions, FP8 scales, FP4
  expert packing, Engram tables, and unsupported surfaces.
- CLI and verifier tooling modeled after =qwen3_infer=, including
  =--token-ids= and =--dump-logits=.

Wave 1 may use CPU/f32 dequantized math for inspectability. It does not need to
be fast enough for production serving, but verifier fixtures must bound the
numeric drift introduced by dequantization and by any pure-Rust reference
fallback.

** Wave 2: multimodal (image input)

Text logits parity is landed on =ultron/mainline=. Wave 2 adds the image input
path so the model can consume the =[IMAGE_START] ([IMAGE]*n_llm_w
[IMAGE_NEW_LINE])*n_llm_h [IMAGE_END]= span layout upstream produces.

Wave 2 delivers:

- First-class vision config (promoted from the deferred struct) and source
  verifier for =vision.py=/=image_processor.py=.
- Image grid planning: =plan_image_grid=, =llm_grid=, =solve_resize_ratio=,
  =safe_resize=, =num_image_tokens=, and the =image_token_types= span layout.
- ViT patch embedding, 2D half-split RoPE, full bidirectional block stack, and
  final ViT norm.
- Aligner downsample (=F.unfold= r=downsample_ratio) + =w1/gelu/w2= and
  =encode_image=.
- Text/vision merge: =merge_image_embeddings= overwrites image-span rows with
  aligner features and learned =image_start/image_end/image_newline=
  delimiters; the image mask (=token_types >= 0=) drives the MoE VL routing bias
  (=bias_vl=) and suppresses the engram contribution on image tokens.
- Vision/aligner/image checkpoint loader tensors.
- Multimodal prompt encoding parity against upstream =encoding.py= and
  =image_processor.py= plus a CLI image path.

Wave 2 keeps the CPU/f32 inspectable-math discipline of Wave 1. Parity is proven
two ways: a tiny upstream-executed reference on CPU with GPU-only kernels
monkeypatched to pure PyTorch, and — where a GPU torch runtime is available — a
real B200 upstream forward. Real-checkpoint image parity remains an explicit
SKIP until released weights are local, and a SKIP is never presented as PASS.

** Wave 3: DSpark (implemented)

DSpark/MTP speculative-draft path (see the Wave 3 tickets 21-25 and the Wave 3
resolution below):

- DSpark/MTP config activation (=dspark_enabled()=) and =mtp.*= checkpoint
  namespace support.
- DSpark Markov head, fp32 confidence head, draft-input construction, and the
  =main_proj=/=main_norm= stage seam.
- =forward_spec= parity against the composed upstream reference for decode-only
  speculative drafts (CPU/f32, Markov-biased greedy drafts).

Not in scope for Wave 3: the outer generation/acceptance loop and real
released-weight parity (SKIP until local weights exist).

** Wave 4: performance and device (accounting + CUDA-gated parity)

Wave 4 lands two seams and defers the rest as explicit TODOs:

- *Cost accounting* (=src/deepseek_v41/cost.rs=): a symbolic
  parameter/FLOP/activation-byte model derived directly from
  =DeepSeekV41TextConfig=, so a caller can size the model and its
  per-forward cost without loading a 510GB checkpoint. MoE sparsity is
  reflected (only =num_experts_per_tok= routed experts run per token).
- *CUDA-gated forward-agreement test*
  (=tests/deepseek_v41_cuda_forward_test.rs=, tags =cuda=/=requires-gpu=):
  builds one tiny DeepSeek V4.1 block + LM head and asserts that the same
  =forward_token_ids= agrees to =1e-4= between the forced-CPU host path
  (=FERRIC_TNSR_DEVICE=cpu=) and the default GPU path (=cuda_ffi= gemm/softmax).
  This proves the DeepSeek forward composes correctly on top of the GPU
  kernels — not just the standalone kernels in =cuda_forward_test.rs=.
  GitHub CI excludes =cuda=/=requires-gpu= tags, so this runs only on a GPU
  host under =--config=cuda=.

TODO after this wave (explicitly deferred):

- Native quantized kernels for FP8/FP4 instead of eager dequantized CPU math.
- Tensor-parallel serving parity beyond static shard-layout validation.

* Non-goals for Wave 1

- No vision/image execution.
- No DSpark speculative decoding execution.
- No distributed all-reduce execution; tensor-parallel shard rules are validated
  and represented, but Wave 1 executes a local single-process model.
- No production-speed FP8/FP4 kernels.
- No silent fallback that changes logits. Unsupported inputs must fail loudly.

** RoPE

DeepSeek V4.1 text RoPE uses adjacent element pairs as complex numbers. The
Qwen3 half-split loader-side permutation must not be copied into this path.

YaRN behavior must match upstream =precompute_freqs_cis=: dimensions whose
wavelength fits the original context keep the base frequency, long wavelengths
are divided by =factor=, and the =beta_fast= to =beta_slow= band is faded by a
linear ramp.

** Attention

Attention is latent and sparse:

- Query path: =wq_a -> q_norm -> wq_b -> [B,S,H,head_dim]=.
- KV path: =wkv -> kv_norm -> [B,S,head_dim]=, with RoPE only over the
  =rope_head_dim= tail.
- Sliding-window KV is causal and ring-buffered.
- Compressed KV is produced only by source layers. Consumers reuse the shared
  compressed cache and top-k index choices.
- Index source layers publish Top-K compressed positions. Later reuse layers
  read the published indices.
- Candidate source layer 20 creates a block-level candidate mask for later
  indexers.
- Output projection is grouped low-rank: reshape heads into =o_groups=,
  apply grouped =wo_a=, then =wo_b= back to =dim=.

** MoE

MoE must preserve the upstream routing distinction:

- Expert selection uses =scores + correction_bias=.
- Expert weights use raw =scores= gathered at selected indices.
- =sqrtsoftplus= scoring is =sqrt(softplus(linear(x)/gate_temp))=.
- =norm_topk_prob= normalizes selected weights with =+1e-20=.
- Selected weights are multiplied by =route_scale=.
- Routed expert outputs are summed and then the shared expert is added.

** Hyper-Connections

The residual stream has =hc_mult= copies. Each sublayer receives a collapsed
input via =pre_mix= and returns to the HC stream with =post= and =comb= mixes.
Mixes are derived from normalized flattened HC state and split through the
Sinkhorn helper into pre/post/comb coefficients.

** Engram

Engram is part of text-only compatibility. It must not be deferred with vision.

Required text pieces:

- Compressed token map compatible with upstream normalization.
- Prime-bucket layout compatible with =EngramLayout.from_args=.
- Prefill and decode hash-state behavior for text token IDs.
- Engram table loading and dequantized lookup.
- Residual update using per-HC normalized signed-square-root gate.

** Image grid planning

Pure functions matching =image_processor.py=:

- =num_image_tokens(n_llm_h, n_llm_w) = n_llm_h*(n_llm_w+1) + 2=.
- =llm_grid= = ceil(ceil(px/patch)/downsample) per axis.
- =solve_resize_ratio= largest aspect-preserving pixel size fitting max tokens,
  including the tall/wide single-column/row collapse branches.
- =safe_resize= shrinks until token cost <= max_n_token.
- =plan_image_grid= applies wh-ratio clamp, min-pixels upscaling, patch rounding.
- =image_token_types= span layout =[IMAGE_START] + ([IMAGE]*n_llm_w +
  [IMAGE_NEW_LINE])*n_llm_h + [IMAGE_END]=, with TEXT=-1 and
  IMAGE_START/IMAGE/IMAGE_NEW_LINE/IMAGE_END = 0..3.

Image byte decoding, PIL resize, and normalization stay out of the Rust path;
patch tensors are supplied by fixtures/reference. The Rust code owns the pure
grid/token-type math only.

** ViT

- =PatchEmbed=: single Linear over flattened =3*patch^2= per patch.
- 2D RoPE is HALF-SPLIT (=x1,x2 = chunk(2); [x1*cos - x2*sin, x2*cos + x1*sin]=)
  over =rope_dim = vision_dim // vision_n_heads // 2=; frequencies stacked from
  (hpos,wpos). This differs from text adjacent-pair RoPE; do not share code.
- =Attention=: full bidirectional SDPA with =wqkv= (bias) and =wo= (bias);
  RoPE applied to q and k only.
- =MLP=: chunked SwiGLU (=w1 -> chunk(2) -> silu(gate)*up -> w2=), no bias.
- =Block=: =x + attn(norm1(x)); x + mlp(norm2(x))= with vision RMSNorm.
- =ViT.forward= = patch_embed -> blocks -> final norm.

** Aligner

- =in_dim = vision_dim * downsample_ratio^2=; =w1: in_dim -> dim=, gelu,
  =w2: dim -> dim= (both with bias).
- Forward reshapes ViT rows to =[n_h, n_w, dim]=, pads to a multiple of r,
  =F.unfold(r, stride=r)= downsample, then =w2(gelu(w1(x)))=. The unfold column
  order (channel-major within each r*r window) must match upstream exactly.

** Text/vision merge

- =encode_image = aligner(vit(patches, n_vit_h, n_vit_w), n_vit_h, n_vit_w)=.
- =merge_image_embeddings= overwrites each image span in the =[B,S,D]= embedding
  (before HC expansion): IMAGE slots take aligner rows in reading order;
  IMAGE_START/IMAGE_END/IMAGE_NEW_LINE take the learned delimiter embeddings.
- =image_mask = token_types >= 0=; =engram_mask = ~image_mask= (image tokens get
  no engram contribution and no n-gram membership).
- MoE gate: when vision is enabled, =bias = where(image_mask, bias_vl, bias)= for
  expert *selection* only; routing weights still come from unbiased scores.

* Verifier ladder

** Level 1: source and paper claims

Commands must be cheap and not require model weights.

- Verify README/model-card claims used by the implementation:
  - multimodal MoE
  - 552B backbone parameter claim
  - CED 20 causal-encoder + 20 decoder organization
  - CSA2 Full/Reindex/Reuse description
  - FP4 main KV cache and one E4M3 scale per 16 channels
  - 1M context support
- Verify technical-report claims mirrored into =paper_claims.json=.
- Fail when source files are missing, stale, or no longer contain the expected
  claim anchors.

** Level 2: config and safetensors metadata

No weight download required.

- Parse =config.json= and =inference/config.json=.
- Assert exact release dimensions and mode fields.
- Parse =model.safetensors.index.json=.
- Assert shard count, total byte size, representative tensor names, and absence
  of Qwen-style tensor names.
- Assert converted namespace expectations from =inference/convert.py=.

** Level 3: isolated math fixtures against upstream code

Use JSON fixtures generated by Python from the mirrored upstream inference
files. Tiny fixtures must run without released model weights.

Required fixture families:

- YaRN frequency and adjacent-pair RoPE.
- Sliding-window top-k indices.
- Candidate block selection.
- Compressor pooling for ratio 1 and ratio > 1.
- Gate routing with =sqrtsoftplus= and correction bias.
- SwiGLU clamp behavior.
- Hyper-Connection mix shapes and doubly-stochastic comb invariant.
- Engram compressed-token map and hash layout.

Each fixture family must be asserted through explicit unit verifier strata:

- *Op verifier*: one function or operation at a time, with deterministic inputs
  and exact or tolerance-bounded expected outputs from upstream Python.
- *Layer verifier*: one model layer component at a time, including attention,
  compressor, indexer, gate, routed expert, shared expert, hyper-connection
  mixer, and engram update.
- *Block verifier*: one complete text block at a time, including HC pre/post
  sequencing, attention residual update, MoE residual update, and published
  shared-attention state.

No full-model parity result counts as sufficient evidence if the corresponding
op/layer/block verifier is missing.

** Level 4: tiny model parity against upstream code

Use a tiny deterministic state dict and the mirrored upstream =model.py= as
the reference. If upstream GPU-only kernels block CPU fixture generation, the
fixture generator may monkeypatch those kernel functions with pure PyTorch
reference implementations while still instantiating upstream model classes and
using upstream field names. The monkeypatch must be documented in the fixture
metadata.

Parity checks:

- Intermediate tensors for every implemented layer component: q path, KV path,
  compressor output, indexer scores/indices, sparse attention output, grouped
  output projection, routing scores/indices/weights, expert outputs, shared
  expert output, HC pre/post/comb mixes, engram gate/update.
- Complete one-block forward parity for representative block modes:
  - sliding-window only =compress_ratio= 0
  - source compressed KV layer
  - index-source layer
  - reuse layer consuming published Top-K indices
  - engram layer
- Final logits for a tiny text-only model.
- =--token-ids= mode to isolate model math from tokenizer differences.

** Level 5: tokenizer and prompt fixtures

Compare prompt rendering/token IDs against upstream =encoding.py= and the
Hugging Face tokenizer or first-party DeepSeek recipe tooling.

Wave 1 only needs text prompt modes:

- Plain prompt token IDs.
- Chat mode with =</think>= suppression.
- Thinking mode with numeric reasoning effort.
- Tool-call DSML prompt strings, but parsing/generation output may remain a
  verifier-only fixture until a user-facing prompt API exists.

Image placeholders must be rejected by the text-only CLI with a clear error.

** Level 6: real checkpoint logits

When local assets exist, compare Rust logits against the upstream inference
runtime on short text-only prompts.

Required behavior:

- Rust binary emits JSON with token IDs, prompt text, vocab size, and
  last-position logits.
- Python reference emits the same schema.
- Comparator reports token-id agreement, max/mean absolute difference, cosine
  similarity, top-1 agreement, and top-5 overlap.
- If token IDs differ, rerun Rust with upstream token IDs to isolate tokenizer
  drift from model math.
- Verification must support both unconverted HF-index metadata and converted
  DeepSeek TP checkpoint directories.
