* Context

Text logits parity needs a command-line surface that can isolate tokenizer
drift from model math. DeepSeek V4.1 has no Jinja chat template; upstream prompt
formatting lives in =encoding/encoding.py= and the model card points production
users at DeepSeek recipe tooling.

* Requirements

- Create =ferric_continuum/tnsr/src/bin/deepseek_v41_infer.rs=.
- Add Bazel target =//ferric_continuum/tnsr:deepseek_v41_infer=.
- Add prompt/tokenizer fixture generation to
  =ferric_continuum/tnsr/tools/deepseek_v41_fixture_gen.py=.
- Add prompt fixture JSON files under
  =ferric_continuum/tnsr/testdata/deepseek_v41/=:
  - =prompt_plain_fixture.json=
  - =prompt_chat_fixture.json=
  - =prompt_thinking_fixture.json=
  - =prompt_dsml_fixture.json=
- CLI arguments:
  - =--model-dir <path>=
  - =--prompt <text>=
  - =--token-ids <comma-separated ids>=
  - =--dump-logits <path>=
  - =--max-new-tokens <n>=
  - =--text-only= default true for this wave
  - =--thinking-mode chat|thinking= for prompt fixture compatibility
  - =--reasoning-effort <1..100>= for thinking prompt rendering
- The CLI must reject:
  - image placeholders in text-only mode
  - DSpark/speculative flags if any are passed
  - token IDs outside =vocab_size=
- The CLI must support =--token-ids= without loading tokenizer files.
- =--dump-logits= must write JSON with:
  - =token_ids=
  - =prompt=
  - =vocab_size=
  - =logits= last-position full-vocab row
  - =model_type= =deepseek_v41_text=
- Tokenizer/prompt verifier requirements:
  - Plain prompt fixture compares rendered prompt and token IDs against upstream.
  - Chat fixture checks upstream =</think>= suppression behavior.
  - Thinking fixture checks numeric reasoning effort rendering.
  - DSML fixture checks prompt-string rendering for tool syntax, even if tool
    output parsing is not exposed in the Rust CLI.

* Out of scope

- No image processing.
- No DSpark decode.
- No full chat application API.
- No requirement to implement the full DeepSeek recipe protocol in Rust if
  fixture parity can be obtained through local prompt rendering plus tokenizer
  files.

* Resolution

Added the text-only CLI =src/bin/deepseek_v41_infer.rs= and Bazel target
=//ferric_continuum/tnsr:deepseek_v41_infer=. Args:
=--model-dir --prompt --token-ids --dump-logits --max-new-tokens --text-only
--thinking-mode chat|thinking --reasoning-effort 1..100=. The CLI preserves the
Qwen3 =--token-ids= isolation (no tokenizer bundled), rejects out-of-vocab ids,
rejects the image token id in text-only mode, and rejects deferred-wave flags
(=--image*=, =--vision=, =--dspark=, =--speculative=, =--spec-decode=,
=--draft-model=, =--mtp=). =--dump-logits= writes
={token_ids, prompt, vocab_size, model_type:"deepseek_v41_text", logits}=
(last-position full row) via a hand-rolled streaming writer.

Extended =tools/deepseek_v41_fixture_gen.py= with =--family prompt=: it imports
upstream =encoding/encoding.py= by path and emits
=prompt_{plain,chat,thinking,dsml}_fixture.json= recording the rendered prompt
string (token IDs are optional and recorded only when a full HF tokenizer is
present locally; only =tokenizer_config.json= is mirrored, so IDs are null with
=tokenizer_status=skipped-no-tokenizer-json=). Added four Level-5 prompt tests
to =deepseek_v41_model_test.rs= (special-token rendering, =</think>=
suppression, numeric reasoning-effort prefix, DSML tool block) and wired the
fixtures into the test =data=.
